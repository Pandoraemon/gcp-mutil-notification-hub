# 成本估算

**结论先行**：中等流量（约 1000 条告警/月）下，本系统的月成本 **< $0.50**，
其中大部分来自 Cloud Logging 摄取，而不是 Pub/Sub 或 Cloud Functions。

---

## 计费口径说明（先读这一节）

网上大多数"Serverless 告警转发成本约等于 0"的估算只算了 Pub/Sub 与 Functions 调用费，
漏掉了三块会真实产生账单的东西。本文的口径**包含**它们：

| 常被漏算的项 | 为什么会产生费用 |
|-------------|-----------------|
| **Artifact Registry** | Gen2 函数的每个版本都会构建一个容器镜像并长期存储。镜像约 150–250 MB，按存储量计费，且**不会自动清理旧版本** |
| **Cloud Build** | 每次部署都是一次构建。免费额度 120 分钟/天，正常使用远用不完，但频繁 CI 部署会超 |
| **Cloud Logging** | 本项目默认 `LOG_LEVEL=INFO`，每条告警产生 3–6 行结构化日志。免费额度 50 GiB/月，之后 $0.50/GiB |

另外两项在本文中**不计入**，但你应该知道它们存在：

- **Cloud Storage**：源码 zip（约 50 KB）与 Terraform state（约 100 KB），四舍五入为 0；
- **网络出口**：发往 IM 平台（飞书 / 企业微信 / 钉钉）的 HTTPS 请求，每条约 2 KB。1000 条 ≈ 2 MB，
  按亚洲区互联网出口 $0.12/GiB 计约 $0.0002。

价格取 2026 年 `asia-east1` 的公开价目，仅供量级参考；实际以 GCP Billing 报告为准。

## 分流量场景对比

| 项目 | 低流量<br/>100 条/月 | 中等流量<br/>1,000 条/月 | 高流量<br/>10,000 条/月 | 告警风暴<br/>100,000 条/月 |
|-----|---------------------|------------------------|----------------------|--------------------------|
| Pub/Sub 消息量 | 免费额度内 | 免费额度内 | 免费额度内 | 免费额度内¹ |
| Cloud Functions 调用 | 免费额度内 | 免费额度内 | 免费额度内 | 免费额度内² |
| Functions 计算（GB-秒） | 免费额度内 | 免费额度内 | 免费额度内 | ~$0.10³ |
| Cloud Logging 摄取 | $0（~0.5 MB） | $0（~5 MB） | $0（~50 MB） | ~$0.25（~500 MB）⁴ |
| Artifact Registry | ~$0.02 | ~$0.02 | ~$0.02 | ~$0.02⁵ |
| Cloud Build | 免费额度内 | 免费额度内 | 免费额度内 | 免费额度内 |
| Secret Manager | ~$0.06 | ~$0.06 | ~$0.06 | ~$0.06⁶ |
| **合计（月）** | **~$0.08** | **~$0.08** | **~$0.10** | **~$0.45** |

¹ Pub/Sub 前 10 GiB/月免费。10 万条 × 2 KB ≈ 200 MB，远在额度内。
² Cloud Functions 前 200 万次调用/月免费。
³ 512 MiB × 平均 0.5 秒 × 10 万次 ≈ 25,000 GB-秒；免费额度 40 万 GB-秒，实际仍在额度内 ——
  表中列出 $0.10 是按"风暴期间冷启动增多、平均执行时间翻倍"的保守估计。
⁴ 每条告警约 4 行 JSON 日志、每行约 1 KB。免费额度 50 GiB/月，
  正常流量下永远用不完；此处列出金额是为了说明"日志才是主要成本项"这个量级关系。
⁵ 2 个镜像版本 × 200 MB × $0.10/GB/月 ≈ $0.04；本表按只保留 1 个版本估。
⁶ 1–2 个 secret × $0.06/月/个（企业微信 1 个，飞书/钉钉 2 个，含访问次数），四舍五入。

## 成本的实际形状

```
Secret Manager  ████████████  $0.06   ← 固定成本，与流量无关
Artifact Registry ████        $0.02   ← 固定成本，与部署次数相关
Cloud Logging   ░░░░░░░░░░░░  $0.00+  ← 唯一随流量线性增长的项
其余            ░             $0.00   ← 全在免费额度内
```

也就是说：**这个系统的成本几乎是固定的，且由两个小额固定项主导。**
流量增长十倍不会让账单增长十倍，除非你把日志级别调成 DEBUG。

---

## 什么情况下成本会失控

| 场景 | 后果 | 预防 |
|-----|------|------|
| `LOG_LEVEL=DEBUG` 忘了改回来 | 日志量增加 5–10 倍，是唯一可能突破 50 GiB 免费额度的路径 | 部署脚本默认 INFO；生产环境不要长期开 DEBUG |
| CI 每次提交都部署 | Artifact Registry 镜像版本无限累积，每个 200 MB | 配置 Artifact Registry 清理策略，只保留最近 5 个版本 |
| 告警回环放大 | 函数故障 → 产生告警 → 触发自己 → 无限循环，同时打爆日志与调用量 | `Router.is_self_referential` 已拦截；仍建议配 Billing 预算告警（本系统自己就能发） |
| DLQ 无人清理 | 消息保留 7 天后自动过期，不产生持续成本，但**告警永久丢失** | 配置 DLQ 深度监控，定期跑 `replay-dlq.sh` |
| `min_instance_count > 0` | 常驻实例按 GB-秒持续计费，从 $0 变成每月数美元 | 本项目固定为 0；冷启动 < 3 秒，不值得为它付费 |

## 与替代方案的对比

| 方案 | 月成本（1000 条） | 说明 |
|-----|------------------|------|
| **本方案（Functions Gen2）** | **~$0.08** | 无常驻资源 |
| Cloud Run（min-instances=1） | ~$10 | 常驻实例费，换来零冷启动 |
| GKE 上跑一个转发服务 | ~$70+ | 集群管理费本身就远超收益 |
| Compute Engine e2-micro | ~$7 | 还要自己管补丁、监控、高可用 |
| 第三方 SaaS（PagerDuty 等） | $20+/用户 | 功能强得多，但对"只想把告警发到 IM 群"是过度设计 |

## 怎么核对真实账单

```bash
# 按服务查看本项目上月费用
gcloud billing accounts list
# 在 Console 中：Billing → Reports → 按 Project 过滤 → 按 Service 分组

# 查看日志摄取量（最常见的意外来源）
gcloud logging read 'resource.labels.service_name="gcp-alerts-to-feishu"' \
  --freshness=30d --format='value(timestamp)' | wc -l

# 查看 Artifact Registry 占用
gcloud artifacts repositories list --location=asia-east1
```

想让这个系统监控它自己的成本，就启用 Billing 数据源：
```bash
./deploy-gcloud.sh --region=asia-east1   # 在"是否启用 Billing 预算告警"处输入 y
```
超过预算的 50% / 90% / 100%，以及**预测**会超 100% 时，都会往所选的 IM 群（飞书 / 企业微信 / 钉钉）发卡片。
预测那条规则最有价值 —— 它在月中就提示"按当前速率会超支"，
而实际支出 100% 触发时钱已经花完了。
